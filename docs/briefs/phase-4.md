## Design decisions (this brief resolves them)

1. **Seed policy (A1) — binding, and a deliberate tightening of PLAN §5.** `seed` is a **REQUIRED keyword-only `int` argument of `simulate`** — no default, no RNG-object parameter (`rng`, `random_state`, `generator` do not exist anywhere in the API). Internally each call constructs a fresh `random.Random(seed)`; **never** module-level `random.*`, never `random.seed()` global state, never an unseeded `Random()`. Bit-identity contract: identical `(fitted, home, away, seed, n_sims, sim_version [, scenario])` → **field-for-field identical frozen output** (frozen-dataclass equality). Provenance echoes `seed`, `n_sims`, and the `SIM_VERSION` string constant on every result. AST-enforced bans (criterion 17): `hash()`-based seed derivation (salted per process for str — would also break cross-process bit-identity), `time`/`os.urandom`/`secrets`/`uuid`/`id()` as seed sources, seeding from `input_digest` or any parameter value. If child seeds are ever needed (none this phase): `sha256(master_seed ‖ canonical_key)` only. **Note recorded deliberately:** PLAN §5 says "all randomness flows through explicitly seeded RNG objects passed by the caller" — this brief **tightens** that wording to *the caller passes a seed; the RNG instance is constructed fresh from it, instance-only, inside the call*. A caller-passed RNG object would make outputs depend on hidden caller-side RNG state (position in the caller's stream), which is exactly the implicit state the constitution bans ("no unseeded, implicit, or global random state"). The DOCS step records this tightening (PLAN §5 one-line clarification, sanctioned by this brief).
2. **Designated randomness module.** `random` is permitted in **exactly one file: `app/simulation/simulate.py`**. Not in `app/simulation/__init__.py` or `constants.py` (they must stay RNG-free), not in `app/models` (Phase 3's ban unchanged), not in `app/scenarios` transform code, nowhere else under `app/` — AST-enforced with positive+negative probes (criterion 16).
3. **Draw primitive stability (A2).** Draws use **`rng.random()` only** — the one method CPython documents as sequence-stable across Python versions for a given seed. Categorical sampling = `bisect.bisect_left` on the cumulative table vs `u = rng.random()`. **AST-banned in the simulation module:** `randrange`, `randint`, `choice`, `choices`, `sample`, `getrandbits`, `shuffle` (attribute calls on any receiver). The draw is factored as a module-level helper taking `(cumulative, u)` so the guard below is unit-testable (criterion 4). `DEFAULT_N_SIMS = 10_000` — documented named constant, caller-overridable, **always echoed** (open question 5 confirms the default). `n_sims < 1` or non-int → `ValueError`. All test simulations ≤ **2×10⁵** draws (120 s health-test budget, KNOWN-LIMITATIONS item 2).
4. **Sampling target — explicit choice, not implicit (A3).** **Chosen: categorical sampling over the truncated (K+1)² matrix, renormalized** — cumulative table built row-major (i ascending, j ascending) from `exp(log_probs[i][j])`, divided by the table sum; `u = rng.random()`; `bisect_left`; **fp-epsilon clamp-to-last-cell guard** when `bisect_left` returns past the final index (possible only from fp rounding at the table tail; clamping touches only the last cell and never shifts mass between cells; the helper makes it probe-able). Consequence, documented in `STATISTICAL-ASSUMPTIONS` §7 before build: MC frequencies deviate from the analytic `outcome_probs` target by at most **`dropped_mass / (1 − dropped_mass)` ≤ ~6.004×10⁻⁴** at fixture-fitted lambdas (K=10). The **alternative** (independent untruncated Poisson draws) is explicitly **rejected this phase** because it would require reporting an `out_of_range_count` (draws outside 0..K) — a second sampling path and a second truth surface — while the truncated-matrix choice reuses exactly the cells whose dropped mass is already disclosed. No `out_of_range_count` field exists; revisiting this requires a future brief that states why (documented as a limitation).
5. **`SimulationResult` field contract (A4 + A9) — frozen dataclass, exact field set:**
   `baseline: FittedParams` (full baseline provenance — model_version, input_digest, config, pooling, flags; embedded by reference, never copied or modified); `scenario: Scenario | None` (spec or `None`); `seed: int`; `n_sims: int`; `sim_version: str`; `counts_home / counts_draw / counts_away: int` (raw integer counts); `analytic_outcome: tuple[float, float, float]` (the exact `outcome_probs` target, H>D>A); `mc_stderr: tuple[float, float, float]` — computed from the **analytic** p as `math.sqrt(p * (1.0 - p) / n_sims)` (that exact expression order is part of the contract), **named `mc_stderr`, never "confidence"/"error"/"ci"** (it measures simulation noise only — A5); `dropped_mass: float`; `convergence_status`, `insufficient_data`, `insufficient_teams` (flags ride through — simulating from a flagged fit yields plausible-looking numbers, so losing the flag is the failure mode). Test tolerances: **never exact equality of frequency vs analytic** — assert `|f − p| ≤ 5·sqrt(p(1−p)/n) + d/(1−d)` per outcome (A4 formula, verbatim), plus **exactly ONE fixed-seed golden pinning exact integer counts** (criterion 3). No λ fields (not in the A9 contract; re-derivable).
6. **`simulate` entry point and scope (A9).** Recommended signature (open questions 3/5):
   `simulate(fitted, home, away, *, seed, n_sims=DEFAULT_N_SIMS, scenario=None) -> SimulationResult` — **no `as_of`, no history, no matches parameter exists to forget; cutoff discipline stays in `fit` alone.** When `scenario` is given, the draws, analytic target, and dropped mass come from the scenario's matrix (built per decision 9) while `scenario` echoes on the result; baseline sim echoes `scenario=None`. Simulation is per-fixture; it consumes one frozen `ScorelineMatrix`-worth of distribution — nothing more.
7. **Why simulate at all (A8) — the scope rationale, stated in the brief and the docs.** Simulation **NEVER replaces `outcome_probs` as the reported single-match probability** — Phase 11 evaluates analytic probabilities; MC noise never contaminates log-loss/Brier/RPS. Legitimate uses: **(i) Phase 12's replay machinery** (same-seed end-to-end determinism replay, stochastic path replay), and **(ii) future aggregate/season-path quantities with no closed form** (season point totals, multi-stage paths, any functional of many fixtures' joint outcomes). A single-match probability has a closed form today; simulating it would add noise to an exact quantity — which is why the simulation exists as infrastructure, not as a reporter.
8. **Scenario op kind — exactly one, bounded (A6).** ONE op kind: a **bounded multiplicative transform on a named parameter** — `attack` (α of a named team), `defence` (β of a named team), or `home_advantage` (h of a named team). Bounds are **named documented constants** `MULTIPLIER_MIN` / `MULTIPLIER_MAX` (recommended 0.5 / 2.0 inclusive — open question 1). **Out-of-range multiplier → `ValueError`; NEVER silent clamping** (clamping = fabricated data, constitution prohibition 4). Every scenario is **labeled hypothetical**: a non-empty caller-supplied `label` echoed on every output; docs state scenario numbers are hypothetical. Transform semantics (literal parameter-scale `α′ = m·α` vs rate-scale `λ′ = m·λ`) is open question 2 — whichever ships is documented in `STATISTICAL-ASSUMPTIONS` §7 with its honest interpretation (under literal parameter-scale, a multiplier dulls/amplifies the parameter's deviation from league mean, direction-dependent on sign — stated, not glossed).
9. **No forged `FittedParams`; one shared cell-math path (A6).** Scenarios **never construct, clone, or modify a `FittedParams`** (AST-enforced: no `FittedParams(` call in `app/scenarios`). Instead, `app/models/scoreline.py` gains a **new shared lambda-pair constructor** (e.g. `lambda_pair(mu, alpha_home, beta_away, alpha_away, beta_home, home_advantage)`) and a **shared matrix builder** (lambda pair + `max_goals` + flags → `ScorelineMatrix`, containing ALL cell math: `_log_pmf` products, dropped mass, flags echo). `scoreline_log_probs` is refactored to delegate to both — **evaluation order preserved character-for-character so Phase 3's full-precision goldens stay green and byte-identical** (no Phase 3 test may change). Scenarios compute transformed parameter *values* from `(fitted, transforms)` and pass them to the same constructor — **one shared entry point, zero copied formulas** (verified by AST: no `lgamma`, no cell formula in `app/scenarios`). Scenario matrices are built with the **baseline's flags** (a transform does not change fit status) plus the transformation spec.
10. **`Scenario` / `ScenarioMatrix` design (A6/A7).** `Scenario` is a **frozen dataclass** carrying `baseline: FittedParams` (full provenance, embedded by reference), `transforms: tuple[Transform, ...]` (**canonical-ordered by the spec key `(team, op, multiplier)`** — construction normalizes order, so shuffled input orders yield field-for-field identical `Scenario`s; duplicate `(team, op)` pairs rejected as `ValueError`, ambiguity never averaged away), and `label: str`. `Transform` is frozen (`team: str`, `op: TransformOp`, `multiplier: float`). `ScenarioMatrix` is frozen (`scenario`, `matrix: ScorelineMatrix` — matrix echoes baseline flags; spec and label reachable through `scenario`). **NO scenario averaging/ensembling, ever** (A6): the API evaluates one scenario per call; alternatives are presented side by side by the caller; disagreement is reported, never collapsed (that is Phase 7's job, "without a silently invented ensemble"). Public API kept minimal (pinned by criterion 14): `TransformOp`, `Transform`, `Scenario`, `ScenarioMatrix`, `build_scenario`, `scenario_matrix`, `MULTIPLIER_MIN`, `MULTIPLIER_MAX`.
11. **Transform applicability — strict, never silently inert.** Unknown team (not in `fit.teams`) → `ValueError` at `build_scenario`. A transform that does not apply to the evaluated fixture (team not playing; `home_advantage` op whose named team is not the fixture's home side) → `ValueError` at `scenario_matrix` — a silently inapplicable transform would present an unchanged number under a hypothetical label, which is mislabeled output (semantics detail: open question 4).
12. **Separation enforcement (A8/P1).** The stricter Phase 4 rules live in the phase's **own NEW separation test** — never in the 612-line hygiene file: `random` only in `app/simulation/simulate.py` (positive+negative probes); the A2 draw-primitive bans; the A1 seed-source bans; no module-level RNG state; import allowlists for both new packages (stdlib whitelist + app allowlist; no `open()`/`os`/`sys`/`pathlib`/`io`/network/wall-clock/env in either); `app/models` stays exactly as strict as Phase 3 left it. The hygiene file changes **only** via AMENDMENT A1 recorded below (+2 entries, nothing else).
13. **Output hygiene (A7).** All outputs are frozen dataclasses of scalars, tuples, enums, and other frozen value objects — **no dict, no set, no list, no iteration over unordered collections**, canonical ordering everywhere, **full-precision floats** (no rounding anywhere), no timestamps, no absolute paths, no environment values (determinism). `inspect.signature` pinning for every new entry point (`simulate`, `build_scenario`, `scenario_matrix`) mirroring Phase 3 criterion 12.
14. **Docs honesty (A5) — authored BEFORE build code.** Per the Phase 3 A1 pattern: the simulation/scenarios section of `docs/STATISTICAL-ASSUMPTIONS.md` is written **before any BUILD code** (contents: MC stderr measures **simulation noise only, NOT model/parameter uncertainty — no confidence intervals exist anywhere in this system**; scenario numbers are hypothetical, conditioned on the in-sample fit and ALL §2 caveats; multipliers are arbitrary knobs, not empirical claims; scenario outputs restate the inherited caveats — draw bias, overdispersion, stationarity, truncation, in-sample-estimate-only; the A3 sampling target and its ≤ ~6.004×10⁻⁴ deviation bound; the seed policy and `random()`-only stability rationale; the analytic-first rule). `KNOWN-LIMITATIONS` gets the Phase 4 entry at phase end (criterion-adjacent, reviewer-verified).

## Dependencies

- **`random` (stdlib) — permitted for the FIRST time, in `app/simulation/simulate.py` ONLY.** Justification: Monte Carlo simulation requires a pseudorandom source; stdlib `random.Random(seed)` is deterministic under a caller-passed seed, instance-only, offline, zero-install, and its `random()` method carries CPython's sequence-stability guarantee across versions — precisely the determinism the constitution demands. No third-party RNG, no numpy.
- **`bisect` (stdlib).** Justification: O(log 121) lookup per draw over the (K+1)² cumulative table; a linear scan would be O(121) per draw at 2×10⁵ draws for no reason. Pure stdlib.
- **`math`, `dataclasses`, `typing`, `enum`** — as needed (sqrt, frozen records, op enum).
- **`hashlib` — NOT used this phase** (one fresh RNG per call; no child seeds needed). Whitelisted-but-unused in the separation test, mirroring Phase 3's `itertools` precedent, so the reserved child-seed mechanism (`sha256(master ‖ canonical_key)`) never forces an allowlist edit.
- **`ast`** — tests only (separation scan, probes).
- **pytest** — already installed; justification unchanged. Explicitly refused: numpy/scipy/pandas and any numeric stack, any bootstrap/CI library, any CLI framework, any RNG beyond `random`.

## Out of scope (A8 scope statement)

- **No bootstrap, no confidence intervals, no "confidence"/"error" bands anywhere.** `mc_stderr` measures **simulation noise only — not model or parameter uncertainty**; there is no mechanism in this system that quantifies parameter uncertainty, and simulation will not be dressed up as one.
- **No randomness in estimation, features, or evaluation.** `app/models` stays 100% deterministic (Phase 3 AST ban unchanged); ingestion, validation, features (Phase 6), and evaluation (Phase 11) are RNG-free; any future need (Phase 12 replay) must come via its own brief extending this discipline.
- **Simulation NEVER replaces `outcome_probs` as the reported single-match probability.** *Why simulate at all:* (i) Phase 12's replay machinery (same-seed determinism replay, stochastic path replay) and (ii) future aggregate/season-path quantities with no closed form (season totals, multi-stage paths).
