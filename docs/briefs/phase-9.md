## Design decisions (this brief resolves them)

1. **`app/backtesting/` is pure — no `app.storage` import; persistence is the CALLER's.** `ALLOWED_APP_IMPORTS["app.backtesting"] = {"app.domain", "app.forecasts", "app.backtesting"}` (AMENDMENT A3, value corrected by AMENDMENT A3' below — self-inclusive, the pattern all eleven existing package entries follow); the harness returns frozen records; a caller-side loop (tests, later Phase 11) stores via `insert_forecast` into a **caller-passed** DB. Manifest fields **not derivable in pure code** (fixture-file sha256s, interpreter version) are **caller-supplied keyword-only parameters echoed verbatim — never `sys`/`os` reads**. The pure/statistical separation (constitution) and PLAN §6 layer 5 hold mechanically.
2. **One new public `matches`-parameter function exactly: `run_walk_forward`; baselines are private inside their own module.** The Phase 8 census (`test_temporal_integrity.py:112–123`) counts public functions whose parameter is named exactly `matches`; the harness is registered (`MATCHES_ENTRY_POINTS` 3→4, AMENDMENT A1) **and given a poison test** (registry 5→6). Every baseline function lives in `baselines.py` **underscore-private** (census-exempt by probe-tested rule, `test_temporal_integrity.py:218`). **Param-renaming is banned**: criterion 7 pins `inspect.signature(run_walk_forward)` with the first parameter **named exactly `matches`** — renaming the parameter to evade the census fails that pin mechanically, not just by prose.
3. **AMENDMENT A3 covers FOUR pinned files, not one (scope corrected by AMENDMENT A3' after the builder's STOP-and-report; architect reconciliation of ruling shorthand — probed evidence, design decision).** The ruling's "phase-5 key-set pins" understates the collision: `test_phase4_separation.py:803`, `test_phase5_separation.py:471`, and `test_phase6_separation.py:424` (+ `:432` exact `PURE_PACKAGES` pin, + `:456`/`:458` self-checks), and — found by the architect during the A3'-ruling verification — `test_phase7_separation.py:391` (+ union `:392–394`, exact `PURE_PACKAGES` four-set pin `:405–407`, source-string pins `:429–432`) all pin the 12-key universe and/or the exact pure set. All five files are amended in A3's exact texts below — the same mechanical pin-collision class ratified at Phases 3–7, strictly stronger, every legacy assertion retained.
4. **Module split: five modules + `__init__.py` (lean, in the `app/decisions` pattern), with baselines isolated for the A1 scope boundary.** `constants.py` (`BACKTEST_VERSION = "backtest-walkforward-v1"` + why-comments; **no knobs** — Phase 7 criterion-1 pattern); `canonicalization.py` (the package's **own** spec of record: sorted keys, fixed separators, `ensure_ascii=True`, no trailing newline, enums as `.value`, tuples as arrays, **no timestamp/path/env/seed in any hashed payload**; no import crosses the stage boundary — `app/forecasts/canonicalization.py` untouched); `record.py` (frozen `BaselineRecord`, `RefusalRecord`, `RunManifest`, `WalkForwardRun`; content hashes at construction `init=False`); `baselines.py` (**all functions underscore-private** — the only module consuming realized scores, isolating the A1 surface for review); `harness.py` (`run_walk_forward` — the single public entry point). Baselines are separated rather than folded into the harness so the realized-result surface is one reviewable file.
5. **Walk-forward mechanics (A3).** Targets = all input matches ordered by `canonical_sort_key` (date primary; the 3-matches/date ties resolved by (competition, season, home, away) — never input order). Per target: `Fixture` = natural key + **kickoff echo from the source `Match`** (the `Fixture` type structurally has no score field; the kickoff rides because it participates in `Forecast` content identity — pin: re-derived fixtures equal `Fixture(..., kickoff=match.kickoff)` for all 60). Pool = input matches **minus the target's natural key**; `build_forecast` enforces the cutoff internally (E3: even a fully unfiltered pool minus the target cannot leak). A `ValueError` from any target becomes a **`RefusalRecord`** (fixture key, status literal `REFUSED_NO_PRE_CUTOFF_HISTORY`, original message) — first-class, ordered with the rest, **never** skipped silently and **never** replaced by a uniform. **Flagged** = prediction emitted with `insufficient_data` or `insufficient_teams` or `convergence_status != CONVERGED` (§5 flags); **clean** = emitted with none. Counts ride the run record: `n_targets`, `n_predictions`, `n_refusals`, `n_flagged`, `n_clean` — with the invariant **60 = 3 + 27 + 30** and **57 = 27 + 30** on the frozen fixtures, both test-pinned.
6. **Run record contract (lean, hash-chained).** `WalkForwardRun`: `predictions: tuple[Forecast, ...]` (canonical order), `refusals: tuple[RefusalRecord, ...]`, `baselines: tuple[BaselineRecord, ...]` (one per target, same order), the five counts, and `manifest: RunManifest`. `BaselineRecord`: `fixture_key` (natural key tuple), `home_frequency`/`draw_frequency`/`away_frequency` (`float | None` — `None` iff MISSING), `n: int`, `status` (enum `COMPUTED`/`MISSING_NO_HISTORY`), `content_hash` (canonical payload, construction-time). `RunManifest` (§11(c), verbatim in substance): `backtest_version`, `forecast_version`, `model_version`, `config_identity` (the Phase 5 `config_identity` of the single spec), `history_canonical_state_digest` (sha256 of `canonical_state()` over the full sorted input pool — the run's input identity; **per-target consumed-history digests already ride each prediction's `input_digest`**, §8 field unchanged), `fixture_file_sha256s` (caller-supplied ordered `(label, sha256)` pairs, echoed), `interpreter_version` (caller-supplied, echoed; `None` stays `None`, never fabricated), and `run_digest` = **sha256 over the canonical serialization of the ordered `(fixture key, content_hash)` list of the 57 predictions** (refusals carry no hash and are outside the digest; their keys are pinned by the accounting criterion). **No timestamp, no wall-clock value anywhere** in any field or hashed payload.
7. **Baselines (A5) — definition verbatim for §12:** per-fixture, chronological **only**: pooled long-run home/draw/away frequencies over realized matches with strictly `date < fixture.date`, **uniform weighting** (one vote per historical match), **no decay**, **no home/away split**; the outcome is decided by goal comparison (H/D/A). **Full-sample baselines are banned — they leak the future.** The first date's **three** fixtures get **MISSING** (`n = 0`, frequencies `None`, status `MISSING_NO_HISTORY`) — **never a fake uniform (⅓,⅓,⅓), never a full-sample fallback** (criterion 10 pins both refusals behaviorally). The record is content-hashed in-process, **re-derivable from the matches alone** (criterion 9 recomputes independently), and **never stored** (criterion 11). Weaknesses ride every baseline: tiny early `n` (0–3 for the first date), synthetic hand-authored data, and the §2f independent-Poisson draw bias that makes the draw frequency the baseline the model is structurally weakest against. The IX-9 phrase "long-run" is realized **as the cumulative strictly-pre-cutoff window** — a truly full-sample "long-run" frequency would see the future and is banned; §12 records this reconciliation.
8. **Test-first gate (A2 §11(b)) is criterion 1 and doubles as A1's registry poison entry.** `test_poisoned_remaining_future_freezes_earlier_predictions` must exist **before** the harness may emit output — the builder writes it first (§12 records the pre-build commitment). Shape: run clean over the full pool; choose cutoff `k` mid-sample (a date index ≥ 1); run again over a pool poisoned **everywhere strictly beyond `k`'s date** (later extreme scorelines, an injected never-seen team, same-day siblings added at later dates — the poison may also alter later *real* matches' scores, since those targets legitimately change); then: every prediction whose fixture date is **≤ k's date** is **field-for-field identical including `content_hash`**; those targets' baselines are identical; the ordered `(fixture key, content_hash)` **prefix** is identical; the **prefix digest** (sha256 over that prefix, same canonical serialization) is identical. Targets beyond `k` may differ — that is correct, not asserted away.
9. **Idempotence (A3/§11(c)) at both levels.** In-process: two invocations over the same input produce identical ordered predictions/refusals/baselines/counts/manifest/`run_digest` (no wall clock, no set-order iteration, no RNG — the AST pin in criterion 12). **Store-level IS run-level** (A4): the caller-side loop inserting all 57 predictions via `insert_forecast` into a `tmp_path` DB returns `True`×57 the first time and **`False`×57 (zero INSERTs)** the second; `verify_all` returns 57 hash-verified forecasts equal to the run's predictions. **No committed DB ships; `SCHEMA_VERSION == 1` pinned.**
10. **Golden run digest: version-local, derived from the real run (Phase 3/4/5/6/7 golden discipline).** The brief pins the **format** (sha256 hex over the canonical serialization of the ordered `(fixture key, content_hash)` list); the literal is **derived by the builder from the real first run** and pinned in criterion 4 with a derivation comment — on any model/fixture/interpreter/canonicalization change: **re-derive and re-document; never widen; never delete**.
11. **No-join enforcement is mechanical, not aspirational (criterion 8).** Three layers over `app/backtesting/**`: (a) **source-token scan** with the Phase 8 scoring tokens plus the new `COMPARATIVE_TOKENS` (criterion 13) → zero hits; (b) **function-level co-occurrence AST scan** — flag any single function that accesses **both** a `Forecast` field attribute (set derived at runtime from `dataclasses.fields(Forecast)`) **and** a `.score` attribute — the mechanical form of "pairing a prediction field with a realized field"; real code passes because score access exists **only** in the private baseline functions and no function touches both surfaces (positive-control probe: a probe function pairing `forecast.outcome_home` with `match.score` in one expression is **flagged**); (c) **public-surface census** — `run_walk_forward` is the package's only public function taking `matches`, and every function in `baselines.py` is underscore-private. Reductions over outcome-aligned arrays (`sum`/`min`/`max`/mean over paired arrays) require the pairing in one function and are therefore caught by (b); no arithmetic-mean-shaped field name exists on any record (Phase 7 criterion-9 pattern, applied to the new dataclasses).
12. **Determinism and no-clock pins for the new package.** `app/backtesting` joins the seedless-by-construction discipline with its own AST assertion in the new test file (no `random` of any spelling; no `time`/`datetime` reference — defense-in-depth in Phase 8 decision 8's pattern; `os`/`sys`/`pathlib`/`io` already banned by `PURE_PACKAGES` via A3). All ordering is canonical (`canonical_sort_key`, sorted dict keys in canonicalization); no environment lookups; the two caller-supplied manifest echoes are the package's only non-derived data and are pinned as echoes.
13. **Single model spec — structural, not conventional (A2(ii)).** The harness signature carries **no** `config`/`spec`/`specs`/`variant`/`variants`/`candidate`/`seed`/`best`/`n`-style knob of any kind; criterion 7 pins the exact parameter names/kinds and extends Phase 8 criterion 8's banned-name scan **to the harness** (extend-not-weaken: Phase 8's scan over the four legacy entry points stays untouched and green; the new file extends coverage). Phase 12/stage-10's improvement loop stays structurally unbuildable from this surface.
14. **Vocabulary (A7) — extend-not-weaken, one new token set, one field-scope extension.** `OUTCOME_COMPARATIVE_TOKENS = ("outperform", "outperforms", "outperformed", "outperforming", "beat", "beats", "beaten", "beating", "hit", "hits", "winner", "champion", "preferred")` — a finite explicit enumeration (the repo's banned-set pattern), compiled with the Phase 8 **strict-segment** semantics and defined **once** in `tests/test_vocab_guards.py` (single source of truth; `tests/test_backtesting.py` imports it — the Phase 4/5/6/8 cross-file pattern). `accuracy` joins **`FIELD_BAN_SEGMENTS` only** (field-name scope) — **never** source-banned (the 9 probed honesty-docstring uses). `score`/`scoreline`/`scored` remain **legal everywhere** (the existing negative-regression pin is extended, never replaced: `baselines.py` legitimately reads `match.score`). Illegal: any reduction pairing prediction with outcome; any private scoring helper (the strict-segment scan flags a `brier`/`log_loss`-shaped helper instantly; the honest-negation allowlist route — never docstring deletion — remains the only sanctioned exception path, unchanged).
15. **Docs placement: `STATISTICAL-ASSUMPTIONS` §12 authored BEFORE any build code (A6), same single-append-hunk discipline as §§3/7/8/9/10/11.** Content, verbatim in substance: the baseline definition (design decision 7); the scored-population accounting (**60 targets = 3 refusals + 27 flagged + 30 clean; 57 predictions = 27 flagged + 30 clean; ≤ 30 clean; no metric computed — evaluated n stays 0**); §11(a)'s bans restated (no "beating", no variant ranking, bins/scored-population pre-registered at Phase 11, synthetic + stationarity caveats ride every walk-forward number); the IX-9 "long-run" reconciliation (design decision 7); and the rule that **any later change to these registrations is a named brief**. §12 is flipped to implemented reality at phase end, as usual; §§1–11 untouched.
