## Design decisions (this brief resolves them)

1. **New package `app/features/` = pipeline stage 4, pure (F1/F2/F5).** Imports allowed: stdlib `{__future__, dataclasses, typing, enum, json, hashlib, datetime}` plus `app.domain` and itself. **No `app.models`, `app.forecasts`, `app/storage`, `app/api`, `app/scenarios`, `app/simulation`, `app/ingestion`, `app/validation`; no `os`/`sys`/`pathlib`/`io`** (A1 adds the package to `PURE_PACKAGES` — strictly stronger); no `random`, no wall clock, no I/O, no environment lookups. `json`/`hashlib` are needed for F3's content hash; `datetime` for ISO date arithmetic only (pre-proven scan-clean by the machinery's own negative controls). Features are descriptive history, consumed by nothing (decision 13).
2. **API (F1, binding): `compute_features(matches, fixture) -> FeatureVector` — the cutoff IS `fixture.date`, computed INSIDE.** No `as_of`/`cutoff`/`date`/time-like parameter exists to forget (criterion 1 pins the signature). Internally: strict `date < fixture.date` over every consumed match — on/after-cutoff matches are silently outside the window (the leakage defense; criterion 3), never an error; prior matches selected in `canonical_sort_key` order, same-date ties resolved there, never by input order. **`ValueError`** (message names the collision) if any match carries the fixture's natural key; **`TypeError`** on a non-`Fixture` target. Cutoff-semantics equivalence with `fit` is enforced by the digest-parity cross-check (criterion 5), not by refactoring `app/models` (F4 byte pins).
3. **Target typing: `Fixture` only, never `Match`** — structural scorelessness reused from Phase 5 decision 3; no domain edit. A feature target that cannot represent a result is structurally incapable of consuming its own outcome.
4. **The record (F3, binding): one flat frozen `FeatureVector`** — field set and order pinned by criterion 4, mirroring `Forecast`'s flat style: fixture natural key (`competition`, `season`, `date`, `home`, `away`), `kickoff: OptionalValue` (availability echo — MISSING never defaulted), `as_of == fixture.date`, `feature_version == FEATURE_VERSION`, `input_digest`, then per side `home_goals_scored_form`, `home_goals_conceded_form`, `home_rest_days`, `home_xg_form`, `home_xg_n`, `home_prior_matches` and the `away_*` six, then `content_hash` (`init=False`, computed at construction under Phase 5's canonicalization style in the package's own `canonicalization.py` — **no import across the stage boundary**; `app/forecasts/canonicalization.py` untouched). **History-dependent fields are `OptionalValue`** (F3, quant no-objection — no `MissingReason` enum exists; MISSING ⇔ `value is None` is the invariant). The two count fields (`*_xg_n`, `*_prior_matches`) are plain `int` where **0 is a true, exact fact** (no prior matches *is* the count), never an imputed estimate — estimates are MISSING, counts are facts; this distinction is documented in §9 so a zero count is never misread as a fabricated zero-value.
5. **Named policy constants (F1) — `app/features/constants.py`, each with a why-comment:** `FEATURE_VERSION = "features-chronological-v1"`; `FORM_WINDOW = 5`; `FORM_WINDOW_POLICY = "MISSING_UNTIL_FULL_WINDOW"` (window > available history → MISSING until the full window exists — open question 1's default; quant permits either shape **per feature**, chosen and documented here); `REST_DAYS_POLICY = "WITHIN_SEASON"` (first match of a season → MISSING; the cross-season alternative, which would report a ~301-day off-season gap as "rest", is explicitly rejected — open question 3); `XG_FORM_POLICY = "MEAN_OVER_AVAILABLE_WITH_N"` (mean over the window's xG-available matches, `n_xg` disclosed, MISSING at `n_xg = 0` — **a different estimator-of-form than a strict rolling-xG window**, documented as such; open question 2). Window scope: the team's last `FORM_WINDOW` matches strictly before the fixture date, **competition- and season-agnostic** (one simple scope; documented limitation — today's fixtures are single-competition; open question 6).
6. **Zero fitted transformers (F2, binding, stated here): every feature is a pure function of `(matches, fixture)`.** No scaling, encoding, normalization, or dataset-level statistics of any kind; team identity is the team name string, never encoded; accumulation order is exactly the canonical window order (full-precision float arithmetic, no rounding, no sort-dependent reduction). Any future fitted transformer must fit **inside the cutoff, per fixture**, with fitted state hash-covered — not this phase (recorded in §9 as a commitment, never built).
7. **Data-layer only (F4, binding):** no estimator, no features-into-fit, no Elo, no feature selection; `SINGULAR_SYSTEM`/insufficient flags ride unchanged; `app/state/` stays unbuilt (roadmap order; no invented dependency). Criterion 16 pins 0-byte diffs on `app/models/`, `app/forecasts/`, `app/storage/` against checkpoint `44b43ea`.
8. **Versioned feature spec (HANDOFF IX-6) = `FEATURE_VERSION` + the named constants + §9's inventory**, in force on every record (`feature_version` echoed). Bump discipline worded **identically to `FORECAST_VERSION`'s (F7):** *any change to the hashed field set, the canonicalization spec, or the derivation semantics requires a `FEATURE_VERSION` bump — the constant is the contract's version.* (A separate frozen spec object is rejected as a second versioned surface for nothing — lean default; open question 4 covers changing the feature set itself.)
9. **Kickoff is echoed, never consumed:** `Fixture.kickoff` availability rides the record for honesty (the HANDOFF IX-6 kickoff availability status; MISSING never defaulted to any fabricated time), but **the computation reads dates only** — the system has day granularity and no within-day ordering discipline (Phase 5 decision 15), so consuming `HH:MM` would claim precision the domain does not have. Features are computed in memory and stored nowhere, so the KNOWN-LIMITATIONS Phase 5 item 12 kickoff-forecast-storage gate is **not** triggered.
10. **Determinism:** no RNG anywhere in the package (`random` AST-banned); no wall clock (date arithmetic only, per the sanctioned negative controls); identical `(matches, fixture)` ⇒ field-for-field identical records including `content_hash` (criteria 3, 4, 6).
11. **No wiring and no storage this phase (F3/F4/F7):** features are consumed by **nothing** — `build_forecast`, `app/storage`, `app/api`, `app/scenarios`, `app/simulation` untouched and uninvited; **no forecast field, no `FORECAST_VERSION`, no Phase 5 golden changes**; no sqlite table, no serialization of vectors, no persistence (`hashlib` exists for the in-memory `content_hash` per F3 — hashing is not storage; `data/` remains not created). Re-derivation from fixtures by `compute_features` suffices; the first consumer arrives via its own future brief with its own version/identity implications.

Updated to implemented reality at phase end, as usual.
